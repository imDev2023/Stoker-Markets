# Code map

What each package holds, in full.
Moved out of `CLAUDE.md` on 2026-11-12 so it is read on demand; `CLAUDE.md` keeps the index.
The text is the original's, one sentence a line.

- `packages/chain` - LaunchLab and CPMM PDAs, instruction builders from the IDLs (Anchor coder), launch, curve and pool trades (transfer-fee aware, `transferFee.ts`; referral share fee), migration, decoder.
  The Creator Lock (ADR 0023): its limits and the rule constraints that admit one in `shape.ts`, the reader, the unlock arithmetic and the claim in `creatorLock.ts`, proven by `tests/backend/src/creator-lock.test.ts`; nothing in `apps/api` or `apps/web` uses it yet.
  Server-only.
- `packages/db` - Drizzle schema and migrations (`pnpm --filter @launchpad/db generate`).
  Every table is declared with `.enableRLS()` (Row-Level Security with no policy, #201: the API is the tables' owner, any other role reads nothing); `src/migrate.ts`'s `runMigrations` applies the migrations and then refuses a database where a `public` table lacks it (`tablesWithoutRowSecurity`).
- `scripts` - the lint's own checks: `claude-md-size.mjs` (`CLAUDE.md` under 20,000 bytes) and `row-security.mjs` (every table of the latest migration snapshot has Row-Level Security; a snapshot's path as its argument checks that one).
- `packages/contract` - zod API contract shared by the API and every client.
- `packages/arweave` - ANS-104 data items signed with ed25519 (the id is known at signing) and ArDrive Turbo's few HTTP endpoints (upload, price, balance, SOL top-up).
  Used by the API and by the stand-in in `tools/stack`.
- `apps/api` - Hono Worker: prepare endpoints, Helius webhook indexer (which also adds graduated pools to the webhook through Helius's API, `src/helius.ts`, when `HELIUS_API_KEY` and `HELIUS_WEBHOOK_ID` are set), Quote Risk Labels (`src/quotes/labels.ts`: from the mint's authorities and extensions and the token list, re-read by the Indexer when a delivered transaction marks a quote mint writable), Copy Protection (`src/copies`: the folded name and ticker keys, the image's difference hash, and the check that `POST /v1/launches/check` answers and `prepare` refuses with 409 inside a launched coin's window, `COPY_PROTECTION_SECONDS`, seven days; the Indexer stores every launch's keys and labels a copy; ADR 0012), read API (the reference is the site's `/api` page; `docs/api.md` points at it), the market behind each Quote Asset (`src/quotes/markets.ts`: TradingView's symbol for the stock or fund a tokenized stock tracks, by the issuer's ticker, and for a coin's own market, by mint; data checked by hand against TradingView's symbol search, never read from a name; #124), the region gate (`src/region.ts`: `GET /v1/region` and the operator's `region-gates` table, ADR 0014), the platform's figures (`src/routes/stats.ts`, `GET /v1/stats`: since the first launch, launches, graduated, the day's volume in SOL and USD; and `change24h` on every launch's market, from `routes/launches.ts`), the chart's marks (`src/routes/marks.ts`, `GET /v1/launches/:mint/marks`, #160, ADR 0018: the key wallets' trades or every trade by candle, wallet and side, the posts on X as Mentions, the operator's Notable Wallets, and the pictures at `/avatars/wallet|x|notable/...` from `src/pictures.ts`), the mentions job (`src/mentions.ts`, job `mentions` on the ten-minute cron, run only when `TWITTERAPI_API_KEY` is set, which only the owner sets: a paid twitterapi.io search per coin that traded in the last half hour, ten coins a run at most), metadata hosting, API keys (`src/apiKeys.ts`), the operator view and fee-change announcements (`src/routes/operator.ts`), and a Cron Trigger (`scheduled`) with five jobs: the graduation watch (plus `reward-tax-lock`, `src/rewardTax.ts`, and the Metadata Upload, `src/metadata.ts`, job `metadata-upload`: posts every launched coin's image and metadata JSON, signed at prepare time, to Turbo, topping credits up with SOL from the operations wallet when refused with 402; also run right after a launch is indexed; ADR 0008), the Quote Registry refresh, the Fee Collector (`src/fees`: claims revenue into the operations wallet, sweeps it to the treasury less the Burn's unspent budgets and what Creators are owed, writes the Ledger) followed on the same cron by the Creator Forward (`src/fees/forward.ts`, job `creator-forward`: pays each Creator their share of collected revenue per Quote Asset, one `creator_forwards` row and one Ledger entry per payment; the shares are computed in `src/fees/creatorShares.ts`, a pool fee collection at the share of the Creator Tier its coin held when it landed, from `src/fees/ladder.ts`, ADR 0020: the one place a tier's share is read, where the Fee Collector, before it collects, counts every climbing coin's Active Days onto `graduations.active_days` and records each tier reached in `creator_tiers`; `GET /v1/creator-ladder`, `creatorForward.ladder` on `GET /v1/platform`, `graduation.creatorTier` on a coin's detail, and the operator's `POST /v1/operator/creator-ladder`, `src/routes/ladder.ts`; and after its wallet forwards the job applies the rule of every coin whose Creator Earnings Destination is not the wallet, `src/fees/rules/`, ADR 0011: `index.ts` walks `rulePots` of `creatorShares.ts`, the one place a coin's pot is computed, `holders.ts` opens a Reward Round of source `earnings` that the Reward Engine pays with a `holder_dividend` Ledger entry per payout transaction, `burn.ts` plans an exact-out buy on the curve or in the pool that burns what it bought, `liquidity.ts` plans a buy, a deposit and a lock in one transaction once the coin has graduated, and `buyback.ts` writes each buyback to `creator_buybacks` before it is sent, settles it, records its two Ledger entries and indexes its trade; `GET /v1/launches/:mint/earnings` in `src/routes/creatorEarnings.ts` is a coin's pot with its rounds or buybacks), volume rebates on the Fee Collector's cron after the Creator Forward (`src/rebates/engine.ts`, job `rebates`, ADR 0021: settles each Rebate Week that has ended, once, as a `rebate_weeks` row with its `rebates`, the `rebates` row's remainder split by the Platform Fees each wallet's trades paid, then pays every wallet whose waiting rebates reach `REBATE_MIN_LAMPORTS` in SOL, a few per transaction, each a `rebate` Ledger entry, which `budget.ts` counts as the row's spending; `GET /v1/rebates` and `GET /v1/wallets/:address/rebates`, `src/routes/rebates.ts`; `POST /v1/operator/jobs/rebates`), the Reward Engine (`src/rewards`: harvests Reward Tax, snapshots holders, pays rounds; the Reward Burn, #183: `burns.ts` withdraws a coin's tax and burns its fixed share in one transaction, kept in `job_transactions` and settled by its signature, one `reward_burn` Ledger entry each, and `burnsOf` for `GET /v1/launches/:mint/rewards`; and the Holding Weight, ADR 0022: every run begins with the Holding Checks due, `checks.ts`, at most 25 coins a run, the never-checked first, each one read of the coin's accounts and one database transaction that writes the day's `holding_checks` row and the changes to `holding_lots`; `weights.ts` is the arithmetic alone, with no database or chain in it (reconciling lots with balances, a wallet's Weighted Holding, a round's payouts), and `snapshot.ts` the one snapshot both sources of round take, the engine's tax rounds and `fees/rules/holders.ts`'s earnings rounds, which reads the lots and never writes them; the steps are `holdingWeights` on a rules version, `HOLDING_DAY_SECONDS` is the day's length, `GET /v1/rewards/rules` carries the steps and `holdingDaySeconds`, a round its `weightedTotal`, a payout its `weightedHolding`, `GET /v1/launches/:mint/holdings/:wallet` a wallet's lots as the latest check left them, and the operator's `POST /v1/operator/rewards/rules` takes `holdingWeights` every time, `src/routes/rewards.ts`; the job's summary carries `holdingChecks` with the day, the coins checked and `leftForLater`) and the Burn and Flywheel (`src/burn`: `engine.ts` runs both budgets, `liquidity.ts` keeps each budget's destination, `burn` or `liquidity`, in `platform_settings` and adds Protocol-Owned Liquidity through the Creator rule's planner, `src/fees/rules/liquidity.ts`, recording `burn_liquidity` and `flywheel_liquidity` Ledger entries and the Fee Key; `GET /v1/burns` and the operator's `PUT /v1/operator/budget-destinations`, `src/routes/burns.ts`; #184), whose budgets, like the sweep's reserve, come from the Budget Table (`src/fees/budget.ts`, ADR 0019: the one place a share of the Platform Net is read; `GET /v1/budgets`, `budgetTable` on `GET /v1/platform`, and the operator's `POST /v1/operator/budget-table`, `src/routes/budget.ts`).
  Every job run is recorded in `job_runs` (`GET /v1/operator/jobs`); a failed run raises a `job_failed` alert, resolved by the next success.

- `tools/localnet` - the local chain with the Raydium devnet programs from committed fixtures: `solana-test-validator` when installed, else the embedded Surfpool runtime (`@solana/surfpool`, `LOCALNET_RUNTIME` to force one), plus platform bootstrap, the taxed Token-2022 quote `TAXQ` (1% transfer fee), and `migrateCurve`, which plays Raydium's crank with a local stand-in migrate wallet.
- `tools/stack` - starts Postgres, local chain, API (and optionally web) for tests, plus an alert sink standing in for the operator's chat webhook, a stand-in for twitterapi.io (`src/x.ts`: the advanced search with its shapes and a 429 on request, the authors' pictures, and `POST /stand-in/posts` for a test's posts; the mentions job on every stack searches it, never the real API), a stand-in for Helius's webhook API (`GET`/`PUT /v0/webhooks/:id`), and a stand-in for ArDrive Turbo and the Arweave gateway (`src/turbo.ts`: upload, price, balance, SOL top-up credited from the local chain, and `GET /<id>`; `GET /stand-in/items` lists what it holds for tests).
  `STACK_LOG_DIR` streams each process's output to files.
  A killed run never reaches `stop`, so a start first removes the `launchpad-test-pg-*` containers (or `launchpad_test_*` databases) of runs whose process is dead.
  Each stack's database belongs to the plain role `launchpad_stack`, which runs the migrations and is the role the API connects as (`databaseUrl`), so Row-Level Security is met as on the hosted databases; `databaseAdminUrl` is the server's superuser on the same database (#201).
- `tools/mainnet` - the go-live scripts the runbook names: `platform-config.ts` builds the unsigned PlatformConfig creation for the cold admin key and decodes one to check it; `lookup-table.ts` creates or extends the Platform Lookup Table from a list of quote mints.
  `jupiter-route.ts` simulates Jupiter's swap of SOL into a Quote Asset on mainnet.
  Read-only on secrets; proven against the local chain in `tests/backend/src/mainnet-tools.test.ts`.
- `tests/backend` - black-box tests: only HTTP API and chain, never internals.
  The one file that opens the database is `row-security.test.ts` (#201), and it reads the catalogue and counts rows as two roles, never the API's data.
- `tests/ui` - Playwright browser E2E on the full stack with a Wallet Standard test wallet (`src/wallet.ts`: the key stays in Node, tests approve or decline each signature), plus pixel baselines at 1440 and 390, light and dark.
  `src/rewardsWeight.spec.ts` is Diamond Hands in the flows (#199): it announces a rules version with steps, shoots the Rewards page's card and a coin's card in the four looks (`screenshots/darwin/flows/diamond-hands-*`), and puts the plain rules back in its `afterAll`; the UI stack's Holding Day is three seconds for it (`src/global-setup.ts`).
