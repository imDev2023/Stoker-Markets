# Traps: the UI suite, its baselines and Playwright

Read before changing anything a pixel baseline shows, adding a spec, or debugging a shot or a flow in `tests/ui`.
Moved out of `CLAUDE.md` on 2026-11-12 so it is read on demand; `CLAUDE.md` keeps the index.
The text is the original's, one sentence a line.

## Baselines and masks

- Text on the launch form, coin page or home page is in nearly every pixel baseline: a wording change re-baselines about 100 images, and a header change 136.
- A date shown in a visual baseline must be a `<time>` element, which the masks cover; a date in plain link text (the round's date on the Holder Rewards card was one) passes the run that writes the baseline and fails the next.
  A new baseline is proven only by a second run, so before committing one look for a clock behind what it frames: `search.png` showed the rewards page's "In force since" through the palette's backdrop (2026-10-07).
  A masked `<time>` inside a `dd` paints the dd's whole box and the row comes out 7px taller than the text: that is the suite's normal shape (`coin-graduated.png`), not a layout bug.
  A `notFound()` page's `performance.measure` page error is vercel/next.js#86060, `next dev` only; the UI fixture ignores that message.
- A baseline that shows the chain's own addresses passes only in the worktree that wrote it: the full footer's PlatformConfig derives from `tools/localnet/.keys/admin.json`, generated per worktree and git-ignored, so the four `home-empty.png` baselines made where the dev chain's keys had been copied in failed everywhere else (2026-10-29); mask every address in a shot (`.mono:not(input)`, as the visual shots do) and never copy keys between worktrees.
  A coin page's "Copy protection until" turns into "ended" 45 seconds after its launch on the test stack, so a shot taken soon after the seed lands either side of it with the run's speed: `coin-longest` reloads until the window has ended.
- A baseline no test names stays stale forever and passes every run: three from before the rename (`coin-graduated-buy`, `coin-graduated-sell`, `coin-graduating`) sat in every look until #90.
  When re-baselining, list the PNGs and grep each name in the specs.
- A Playwright spec no project's `testMatch` names never runs and the suite stays green by its absence: `copies.spec.ts` sat unmatched through two full runs of #122 (2026-10-27).
  When adding a spec, add it to the flows regex in `tests/ui/playwright.config.ts`, check the run's list names it, and re-baseline in the same PR: #121 added `copies.spec.ts` to the regex alone, and its launch left `board.png`, `board-filtered.png` and `assets.png` one coin stale on main until #127 and #129 each corrected them (2026-10-28); a `dt` has no accessible name (the term role takes none from its content), so find one by text, never with `getByRole("term", { name })`.
- Every launch baseline shows the pair and launch type rows (`OptionRow`) and the summary's preview card (`CoinCard`, which the landing's Trending draws too): a change to either re-baselines every launch image, and a change to `CoinCard` the landing's too.
  The preview's opening price arrives from a launch quote after the load, so a launch shot waits for it (`previewPriced` in `visual.spec.ts`), and a shot of the signing panel holds the test wallet's answer (`wallet.holdNext()`).
- The revenue page's "Swept to the treasury so far" SOL wavers by a few lamports between UI runs (7.959784 one run, 7.959779 another, the sweep's own costs), and so does the Ledger's own sweep entry (its amount flipped a proving run on 2026-10-31), so `visual.spec.ts` masks both; a UI baseline is proven only by a plain run after the one that wrote it, and the layout unit's nine runs (2026-10-11) caught that flake and two real faults that way.
  Never size a table column in `em` on its heading when the cells' font is larger: the trades table's time column was `5.5em` of an 11px heading, and "41s ago" against "1m ago" in the 13px cells moved every column.
- The UI suite's masks (2026-10-29): `dynamic` masks every `.mono`, so a figure that must stay visible in a baseline never carries `mono` (`Price` is the `.price` primitive); the wallet avatar's hues come from the address, which every run draws afresh, so `[data-avatar]` is masked; a masked `time` inside a content-sized flex item takes its own text's width, so its box is fixed in `screenshot.css` (`[data-priced] time`); a coin row's five-minute change (`[data-label="5m"]`) is masked too, since it reads the seed's trades only while a shot lands within five minutes of them and 0.0% on a slow run (the board and asset baselines, 2026-11-06); a board card's age (`[data-age] time`) and a board row's on a phone (`[data-label="Age"] time` under 760px) have fixed boxes for the same reason, since "4m ago" against "15m ago" moved the mask and the figure beside it on a slow run (2026-11-09); `--update-snapshots=changed` rewrites any byte-different image under `maxDiffPixelRatio: 0`, so measure each rewritten baseline against `HEAD` with a pixel diff before reviewing (148 rewritten, 130 real on #151), and a baseline is proven only by a plain run after the one that wrote it.

## Screenshots and Playwright

- A visual test that clicks a preset or a chip and then shoots the panel must park the pointer first (`page.mouse.move(0, 0)`): the pointer rests on what it clicked and draws its hover into the shot now and then, which passed the run that wrote the baseline and failed the next (`trade-sol-no-route` and `trade-pool-buy-quote`, 2026-10-25; `trade-sol-quote` on 2026-10-26, after which every panel shot that follows a click parks it).
- A Playwright element screenshot taller than the viewport is taken scrolled, with the sticky site header drawn over its top (wallet address included); `visual.spec.ts` unsticks the header for those shots, and zeroes the page's `scroll-padding-top` with it: Playwright scrolls an element that fits the viewport into view and captures the viewport alone, so with the 88px padding kept a panel taller than the viewport less the padding stops with its top at the padding and its bottom off screen, blank in the shot, whenever the clicks before it left the page scrolled elsewhere (`trade-sol-quote.png` on the phone, 2026-10-27, when the head's new links moved the page under those clicks).
- On a cold `next dev` load, hydration can land after `networkidle`, so a UI check that needs client script (a fitted `PairMark`, anything set in an effect) must poll, as `expectNoTruncatedText` does.
  A screenshot taken before hydration fails the test another way: Playwright hides the caret by writing an inline style on every field and restoring it after, so React, hydrating inside that window, logs a hydration mismatch (`board-empty.png`, 2026-10-26); a shot taken straight after a load waits for `expectHydrated` first (`snap` and the empty spec do).
  Anything on a page that carries the stack's own port or address must be masked (`[data-live]` on the API page's quickstart), or the baseline passes the run that wrote it and fails the next.
  An element shot of a modal `<dialog>` blends its anti-aliased edge with the page beneath through the translucent backdrop, so the page is hidden under it for the shot (`tests/ui/src/dialog.css`, passed with `screenshot.css` since a call's `stylePath` replaces the config's; `trade-disclaimer.png`'s bottom row, 2026-10-26).
- A Playwright mask paints an element's whole box even where a scrolling list clips it, and `snap` scrolls the page under a resting pointer, which hovers whatever passes beneath (an open picker then scrolls its list): `visual.spec.ts` parks the pointer first and hides the picker's balances instead of masking them.
- Running a second `playwright test` in `tests/ui` while a suite runs wipes its `test-results` and fails it; pass `--output` elsewhere.
  To diagnose one visual shot, run the real test with its seed alone, `pnpm exec playwright test --project seed --project visual-<look> --no-deps -g "seed the board|<title>"` (about 2.5 minutes on a throwaway stack), with a `console.log` of scroll and boxes in the test if needed; a hand-rolled Playwright script outside the suite's fixtures never got the test wallet connected and cost hours for nothing (2026-10-27).
  A stack start whose web dies compiling the Google fonts under Turbopack (`next/font/google queries have exactly one entry`) is #38, transient: start it again.
  A UI run whose web log says "There was an issue establishing a connection" to `fonts.googleapis.com` (the Mac just restarted, 2026-11-09) rendered the Mac's own copy of Bricolage Grotesque and the system monospace instead, and the empty-state shots failed by 30 to 15,000 pixels of glyph shape (the hero's headline a touch wider) with every later project skipped: not the branch; check `STACK_LOG_DIR`'s web log before reading the diffs, and run again once `curl` reaches Google Fonts.
- A Playwright full-page screenshot doesn't scroll, so `loading="lazy"` images far down a long page load or not by timing; `snap` in `visual.spec.ts` scrolls through the page first.
  Never force `loading="eager"` from a test: it causes a hydration mismatch.
  Masks paint even over elements hidden inside a closed `<details>`, so mask only visible ones.
- Playwright won't click an `aria-disabled` option without `force: true`.

## Flows and fixtures

- A test that types into the trade panel right after connecting must first wait for the panel's "Pay with" choice to settle: the panel never switches under a typed amount.
- Fill the launch form's airdrop only after the wallet is allowed and connected: the option appears once `launch-permissions` answers.
- The header and footer link to Stoker's X and Telegram (`apps/web/src/lib/site.ts`, placeholder URLs until the owner replaces them) under the names "X" and "Telegram", which the launch form's fields and a coin page's links share: a test locator for those must be scoped (`getByRole("textbox")`, `getByRole("article")`), or it matches two or three elements.
  Likewise the board's search and the landing's candidate field (`LandingSearch`) are both a `searchbox` named "Search coins": scope a locator to the page's region when both could be on the page.
- The board's controls (search, Sort, the asset bar with every kind) render before the first coin: the owner opens the dev site on an empty database and judges a feature by that view (2026-10-07, when an empty-state branch hid all of them).
  `empty.spec.ts` pins the controls and the rail's kinds (on `/coins` since #90) and the landing's first-launch invitation on `/`; never put a control behind an empty state.
  The rail's assets are only those coins are paired with, so an empty board shows the kinds alone.
- A Holding Day lasts three seconds on the UI stack (`global-setup.ts`, for `rewardsWeight.spec.ts`), so under a rules version with steps a Holding Lot reaches its next step within seconds or minutes, and a wallet's Diamond Hands on a coin's card (its weight, its rows) changes by itself between two page loads.
  A flow that compares the card with `GET /v1/launches/:mint/holdings/:wallet` reads both again until they agree (`toPass`), and the card's four baselines are shot with one answer of the API held for the page (`page.route` with `route.fetch()` and `fulfill({ response, json })`, which keeps the real answer's CORS headers), read while the two lots counted differently.
  Never shoot a weight straight off the running stack.
- Only `rewardsWeight.spec.ts` may put a Reward Round rules version with steps in force on the UI stack: every other flow works its payouts out with each coin counted once, and the visual projects run before the flows and must never see the Diamond Hands card or block.
  A rules change needs a minute's notice whatever the stack's lead time, so that file costs two waits of a minute, and its `afterAll` waits the plain version in even when a test failed.
  The stack's treasury is an address with no key, so no test can connect as it: the card's line for the treasury is shown the API's answer with `flat` set.
- The UI fixture records the disclaimer's acceptance before every page load (`DISCLAIMER_KEY` in `tests/ui/src/fixtures.ts`), so no test or baseline meets the welcome: a test of the welcome sets `test.use({ firstVisit: true })`, and a test of the launch or trade disclaimer calls `forgetDisclaimer(page)` after the load, or the dialog never comes.
  Escape closes a modal `<dialog>` by itself and Chromium may not let `cancel` prevent it, so anything the close must do (the welcome's acceptance) hangs on `close`, never on `cancel` alone.

## Layout checks: overflow, truncation and the pair

- The UI tests' overflow check flags any element whose box runs past the viewport, even inside a scrolling container; a sideways-scrolling `pre` must hold plain text, not a `code` child.
- A visually-hidden span (absolutely positioned) inside a box that scrolls sideways is positioned against the body under the suite's screenshot styles (`body { position: relative }`), at its chip's unscrolled x, outside the box's clip, and widens the page by hundreds of pixels while no visible element overflows: give such a scroller `position: relative` (the asset bar and the landing's trending row, 2026-10-31).
- The UI suite's truncation check fails any element with `text-overflow: ellipsis` whose text overflows, and `PairMark` fits itself to its parent's width: in a flex row give it a box of its own (`CoinRow`'s `.pairBox`) and let the name beside it wrap, or the widest seed ticker is cut (#90).
  A box that wraps the pair itself (the coin page's title row) reports the pair's own width as the room, so the fit lifts the pair's own `max-width` while it reads the room, reads it at subpixel precision and keeps the set size when the pair fits within half a pixel.
  Under reduced motion (the suite's visual projects) `globals.css` shortens every element's transition to 0.01ms without naming a property, so every element then transitions every property, inherited ones included: `PairMark`'s parts transitioned their inherited size, a measurement in the same task as the reset read the old size, and the fit drifted from refit to refit (the title pair at 27.6px or 28px, the hero pair anywhere between 80px and 90px, found by probing loads under the suite's own projects, 2026-10-31).
  Setting `transition: none` on the pair alone did not help, since the parts transition on their own: the pair and its parts carry `transition-property: none` in their stylesheet.
  Any element whose size a script measures right after setting it needs the same; `width: max-content` on the pair's box is not a fix (it emptied the pair).
- A sideways-scrolling row needs `position: relative`: the `visually-hidden` spans inside it (a pair's spoken form, a full price) are absolutely positioned against the page and widen it by a pixel each at their scrolled positions, far past the edge (the landing's trending row at 390, 2026-10-29); `expectNoHorizontalOverflow` skips what sits inside a `[data-scrolls]` box that itself fits.
  The UI suite's screenshot projects (`empty-*`, `visual-*`) run with `reducedMotion: "reduce"`, so anything that cycles or animates must hold still under it (the hero's pair cycle holds its first asset) or its baseline is a lottery; the flows do not, since a test that reads a colour right after a toggle sees a near-instant transition still at its start (`board.spec.ts` polls it).
  `snap`'s decode wait covers only images within the page's width: a lazy image hidden sideways in a scrolling row never loads without a sideways scroll, and `img.decode()` on it never settles (the phone `home` shot hung 88 s on the trending row until its six images stopped being lazy).
- The landing's figures strip is one row of equal columns on a desktop with each value scaled to its column (`min(var(--text-figure-xl), 20cqi)`, every `.stat` a container) and never broken across lines: six figures at 1440 broke "0.06" and "SOL" in two (2026-10-29).
  A `PairMark` inside a flex column that sizes to its content measures a box no wider than itself and shrinks the pair by a hair that varies between runs (the phone `home` baseline flaked by 283 pixels): give the column the row's remaining width (`flex: 1 1 auto`, `min-width: 0`), as `CoinRow`'s grid column does.
